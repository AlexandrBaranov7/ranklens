## D-001. src-layout вместо плоского пакета — принято

**Контекст.** Требование курса — установка через pip. Частая ошибка: тесты
проходят локально, потому что импортируют пакет из рабочей директории,
а собранный wheel сломан (забыт файл, `py.typed` не попал в сборку).

**Решение.** Пакет лежит в `src/ranklens/`. Тесты импортируют только
установленную версию. В CI отдельная задача собирает wheel, ставит его
в чистый venv и запускает `ranklens --version` вне репозитория.

**Альтернативы.** Плоский `ranklens/` в корне — проще, но скрывает ошибки упаковки.

## D-002. Poetry, lock-файл, версия в pyproject — принято

**Контекст.** Без lock-файла CI ставит последние версии ruff/mypy/pytest,
и их новый релиз может сломать CI без изменений в коде.

**Решение.** Управление зависимостями и сборка — Poetry 2.4 (бэкенд `poetry-core`).
Метаданные — в стандартной таблице `[project]` (PEP 621), dev-инструменты —
в `[dependency-groups]` (PEP 735), `poetry.lock` коммитится.
Версия — только в `pyproject.toml`; `__version__` читается через
`importlib.metadata.version("ranklens")`.

Проверено: для numpy Poetry сам разводит версии по маркерам Python
(на 3.14 — более свежая ветка), так что один lock не прижимает все Python
к самой старой совместимой версии.

**Альтернативы.** hatchling + pip — было в первой версии, без lock-файла.
uv — быстрее, тоже с lock-файлом; выбран Poetry, потому что с ним есть
опыт работы.

## D-003. Python >= 3.11, CI на 3.11–3.14 — принято

**Контекст.** Свежие numpy уже требуют 3.12, pandas 3 — 3.11.

**Решение.** Нижняя граница 3.11. Разработка ведётся на 3.11,
CI проверяет 3.11–3.14 × Linux/macOS/Windows. Нижние версии numpy/pandas
в `dependencies` — те, с которыми реально проходят тесты.

## D-004. Позиции с нуля, ранги с единицы — принято

**Решение.** В структурах данных — `position` с нуля (индекс в кортеже).
В формулах — `rank = position + 1`. Имена переменных различают эти понятия.

**Почему.** Формулы метрик (log₂(rank + 1), 1/rank) и propensity (1/rank)^η
записаны для рангов с единицы; ошибка на единицу в дисконте — самый частый
тихий баг в метриках ранжирования.

Линейная история с сохранением отдельных коммитов PR и их дат.

засоряют историю.

## D-007. `RankedList.docs` — tuple, а не list — принято

**Контекст.** Первоначальный дизайн: `RankedList` — `frozen` dataclass с полем `docs: list[DocId]`.
`frozen=True` запрещает переприсваивание атрибута, но не мутацию списка:
`ranked.docs.append(...)` сработает. Кроме того, dataclass со списком
нехешируем, хотя `frozen` обещает обратное.

**Решение.** `docs: tuple[DocId, ...]`, `scores: tuple[float, ...] | None`.
Список остаётся там, где нужна мутация: буфер накопления строк текущего запроса
в `iter_run` — сначала `list.append`, при смене query_id — `tuple(buffer)`.
Это и есть обоснование `list` для чеклиста: изменяемая структура для построения,
неизменяемая — для результата.

**Проверки в `__post_init__`.** `docs` и `scores` — именно `tuple` (mypy не защищает
вызывающий код без типизации, `TypeError`); длина `scores` совпадает с `docs`
(`ValueError`, ошибка программиста); документы в выдаче уникальны —
иначе `DuplicateDocumentError`, это ошибка данных (проверка через `set`, O(n)).

## D-008. Исключения: аргументы в `args`, текст в `__str__` — принято

**Контекст.** Исключение со своим `__init__(self, line_no, raw, reason)`
по умолчанию не переживает `pickle`: распаковка вызывает `cls(*self.args)`,
а в `args` лежит одна готовая строка.

**Решение.** Конструктор передаёт исходные аргументы в `super().__init__`,
хранит их в атрибутах, текст собирается в `__str__`. Тест проверяет
`pickle`-round-trip для каждого класса иерархии.

## D-009. Архитектурные границы проверяются тестом — принято

**Решение.** `tests/test_architecture.py` разбирает AST всех модулей пакета
и сверяет импорты с таблицей из CONTRIBUTING (раздел 4). Учитываются и импорты
внутри функций. Правило из документа, которое не проверяется, со временем
перестаёт соблюдаться.

**Альтернативы.** `import-linter` — готовый инструмент, но ещё одна зависимость
и конфигурация; свой тест — около сотни строк, понятных целиком, и сам проверен тестами на заведомо плохих импортах.
